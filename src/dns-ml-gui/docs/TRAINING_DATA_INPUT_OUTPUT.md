# DNS ML Training Data Input / Output

## Purpose

The Learning Navigator uses a controlled four-step training-data workflow.

1. Upload JSON DNS training files.
2. Merge and verify every uploaded JSON file.
3. Analyze the merged dataset and extract ML features.
4. Clear uploaded/prepared training data and start a new cycle.

Machine learning is locked until Steps 1-3 finish successfully.

## Input-format setting

The training-input policy is stored here:

`/opt/dns-ml-gui/config/training_input.json`

Current policy:

- input format: JSON / JSONL, including Zeek JSON `dns.log`
- accepted file extensions: `.json`, `.jsonl`, and `.log`
- archives: disabled
- multiple files: allowed
- all uploaded files are merged together
- every file must pass merge verification before ML learning is enabled

The Streamlit per-file upload-size setting is stored here:

`/opt/dns-ml-gui/.streamlit/config.toml`

## Accepted JSON structure

The GUI accepts Zeek DNS JSON/JSONL in any of these forms:

1. One JSON object per line (recommended Zeek JSON / NDJSON style), saved with a `.json`, `.jsonl`, or `dns.log` filename.
2. A normal JSON object.
3. A normal JSON array whose elements are JSON objects.

During Step 1 the system validates the JSON and normalizes every uploaded file into one-JSON-object-per-line form before merge.

Archives (`.zip`, `.tar`, `.tar.gz`, `.tgz`) and compressed `.gz` files are not accepted by the GUI training uploader. A `.log` file is accepted only when it is the JSON one-object-per-line `dns.log` produced by Zeek or the DNS Log Preparation page.

## Input files

### Browser-upload originals

`/data/dns-ml/training_upload/incoming/*.json`, `*.jsonl`, and JSON `*.log`

These are the original JSON files uploaded by the user for the current training cycle.

### Normalized merge inputs

`/data/dns-ml/training_upload/files/dns_upload_000001.json`

`/data/dns-ml/training_upload/files/dns_upload_000002.json`

`...`

Every selected JSON, JSONL, or JSON `dns.log` file is normalized and stored separately as canonical one-object-per-line JSON before merge. If five files are uploaded, five normalized JSON input files are staged.

The merge process is pointed to this directory, so **all staged JSON files are merged together**.

### Upload manifest

`/data/dns-ml/training_upload/upload_manifest.json`

Contains original filename, staged filename, SHA-256, file size, and normalized JSON-record count.

### Workflow state

`/data/dns-ml/training_upload/workflow_state.json`

Controls sequential Step 1 -> Step 2 -> Step 3 -> Step 4 operation and the ML learning gate.

## Step 2 merge outputs

`/data/dns-ml/zeek/merged_dns.jsonl`

Deduplicated merged DNS training dataset containing records from all uploaded JSON files.

`/data/dns-ml/zeek/stats.json`

Summary statistics used by the Zeek DNS Log Manager cards.

`/data/dns-ml/zeek/stats.sqlite`

Temporary/statistical merge database persisted for diagnostics.

`/data/dns-ml/zeek/source_ip_stats.csv`

Per-source-IP query/capture-window statistics.

`/data/dns-ml/zeek/merge_status.json`

Current/final merge status, file counts, processed counts, invalid lines, and record counts.

`/data/dns-ml/zeek/merge_manifest.json`

Manifest generated by the Zeek merge manager.

`/data/dns-ml/zeek/merge.log`

Merge command output displayed by the GUI.

## Step 3 feature outputs

`/data/dns-ml/features/dns_training_features.csv`

Validated ML feature dataset.

`/data/dns-ml/features/dns_training_feature_summary.json`

Feature count, training windows, source-IP count, first/last timestamps, and ready-for-ML state.

`/data/dns-ml/features/dns_training_feature_status.json`

Feature-extraction state/stage/progress/error information.

`/data/dns-ml/features/dns_training_feature_extract.log`

Feature-extraction command output.

## ML learning input and gate

The current model-learning controllers remain based on the verified merged DNS dataset:

`/data/dns-ml/zeek/merged_dns.jsonl`

Step 3 also creates the validated feature artifact:

`/data/dns-ml/features/dns_training_features.csv`

The Autoencoder and Isolation Forest start functions are blocked at the backend until:

- upload batch exists,
- every staged JSON file was included in the merge,
- merge verification passes,
- invalid-line count is zero,
- merged dataset is non-empty,
- feature extraction succeeds,
- validated feature dataset is non-empty.

## Step 4 reset

Step 4 deletes only the uploaded/prepared training-cycle data:

- `/data/dns-ml/training_upload/*`
- prepared `/data/dns-ml/zeek/*` merge outputs
- `/data/dns-ml/features/dns_training_*`
- `/data/dns-ml/training/*`

It does **not** delete:

- `/opt/zeek/logs`
- trained models
- alerts
- scoring cursors/buffers
- scoring configuration
- cron configuration
